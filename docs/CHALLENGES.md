# Project Challenges Log

A running list of problems met while building SecureSearch AI, how each was handled, and what we learned.
**Rule (owner, 2026-10-19):** every new challenge is added here as soon as it is met, for the whole project, in every phase. Newest entries go at the bottom of their phase section. Never delete entries; change the status instead.

Status values: `Resolved`, `Workaround`, `Open`, `Needs owner decision`.

| # | Date | Phase | Challenge | Impact | What we did | Status | Lesson |
|---|---|---|---|---|---|---|---|
| 1 | 2026-10-19 | 0 | The blueprint PDF file name says v1.1, but the document says "v1.2 FINAL". | Risk of following the wrong version. | Treated the internal version (v1.2 FINAL, frozen 7 Oct 2026) as the source of truth. | Resolved | Always check the version inside a document, not its file name. |
| 2 | 2026-10-19 | 0 | The PDF viewer tool could not render pages (no `pdftoppm`). | Could not read the blueprint directly. | Extracted the text with `pdftotext` and read that. | Resolved | Keep a text extraction fallback for PDFs. |
| 3 | 2026-10-19 | 2A | The local project folder had 60 tracked files deleted from the working tree, and the GitHub repo had been recreated empty (no `main`, no tags, no PR history). | Nothing to build on; a PR had no base branch ("nothing to compare"). | `git restore .` (non-destructive), then pushed local `main`, tag `v0.1` and the old feature branches after the owner confirmed. | Resolved | Check `git ls-remote origin` before assuming the remote matches local tracking branches. A stale `origin/main` can hide a missing remote. |
| 4 | 2026-10-19 | 2B | Docker Desktop was not running when the phase started. | No services, no integration tests. | Wrote code first, verified once the engine was up. | Resolved | Check the Docker engine at the start of every phase. |
| 5 | 2026-10-19 | 2A/2B | `alembic.ini` from 2A had no logging sections and no `prepend_sys_path`, so `alembic` crashed (`KeyError: 'formatters'`, `No module named 'app'`). | Migrations could not run. | Completed `alembic.ini`. | Resolved | 2A claimed Alembic was configured but it was never run. Run every tool once before marking it done. |
| 6 | 2026-10-19 | 2A/2B | `greenlet` was missing, so SQLAlchemy's async engine failed to import. | First real DB call failed. | Pinned `greenlet==3.5.6` (ADR 022). | Resolved | Health checks that only open a socket do not prove the ORM works. |
| 7 | 2026-10-19 | 2B | An old Postgres volume from 9 Oct had a different password than the new `.env`. | `password authentication failed`. | Changed the role password inside the existing database (`ALTER ROLE`) instead of deleting the volume. | Resolved | The Postgres password is fixed when the volume is first created; changing `.env` later does not change it. Do not delete data to fix a password. |
| 8 | 2026-10-19 | 2B | Async SQLAlchemy connections break when each test uses a new event loop. | Flaky or failing tests. | Used one session-wide `TestClient` (one loop) and passed refresh cookies by hand for multi-device tests. | Resolved | Design async test fixtures around a single event loop. |
| 9 | 2026-10-19 | 2B | Mailpit's `DELETE` returns plain text `ok`, not JSON. | Test helper crashed on JSON parsing. | Made the helper tolerate non-JSON replies. | Resolved | Do not assume every API call returns JSON. |
| 10 | 2026-10-19 | 2B | The backend image does not mount the source folder, so edited tests and code were not inside the container; copied files were root-owned and read-only for the app user. | Tests ran old code; an in-container edit failed with "Permission denied". | Used `docker compose cp` to copy files, and `exec -u root` for the one deliberate mutation check. | Workaround | Rebuild or copy before testing. Consider a bind mount or `docker compose watch` later (Phase 9). |
| 11 | 2026-10-19 | 2B | Importing `tests.conftest` from a test file ran the database setup a second time. | Test database could be dropped mid-run. | Moved shared constants into `tests/constants.py`. | Resolved | Never import a conftest module from tests. |
| 12 | 2026-10-19 | 2B | A long shell heredoc with many files failed to parse and created nothing. | Lost a step. | Created the files with the file-writing tool instead. | Resolved | Do not batch many documents into one shell command. |
| 13 | 2026-10-19 | 2B | FR-25 asks for admin-initiated password reset, but the frozen API contract has no endpoint for it. | Requirement and contract disagree. | Not built. Recorded in ADR 023 item 3. | Needs owner decision | Frozen contracts need a Change Request to add endpoints. |
| 14 | 2026-10-19 | 2B | The persona table (Executive, IT, Compliance) does not match the 8-department seed list. | Seed data could not follow the blueprint literally. | Mapped Vikram to Company-wide, Dev to Engineering, Nina to Legal (ADR 023 item 4). | Needs owner decision | Cross-check tables inside a spec before coding seeds. |
| 15 | 2026-10-19 | 2B | Phase 1 `STATUS.md` still says "waiting for owner review" although Phase 1 is signed off and tagged `v0.1`. | Stale status file. | Left untouched (finished phase); noted in STATUS. | Open | Update STATUS.md at sign-off. |
| 16 | 2026-10-19 | 2B | The first PR compare link had the PR title in the URL, and the GitHub default branch was `feat/auth-backend` after the repo was recreated. | Owner could not create the PR. | Gave a corrected link (`main...feat/auth-backend`) and asked the owner to set the default branch to `main`. | Resolved | Give the owner exact, tested links. Check the default branch after a repo recreate. |
| 17 | 2026-10-19 | 2C | The access token must live only in memory, so Next.js server code cannot see who is signed in. | Server-side route protection is not possible. | Planned client-side route guards; data stays protected by the API. | Workaround | Document honestly that page shells are public, data is not. |
| 18 | 2026-10-19 | 2C | The welcome tour needs a "seen" flag, but the backend has no such field and the API contract is frozen. | Tour may show again on another browser. | Planned a per-user `localStorage` flag. | Workaround | A Change Request would be needed for a server-side flag. |
| 19 | 2026-10-19 | 2C | After a mutation check on the 2B backend, the running server kept the broken (mutated) code in memory even though the files were restored; the lockout looked "off" in the browser while the test suite passed. | Live behaviour differed from the tests; found only by a real browser test. | Restarted the backend container; lockout confirmed (5 x 401, then 429). | Resolved | Restart the server after any in-container edit or file copy. `--reload` is not reliable with `docker cp`. Always re-check live behaviour, not only tests. |
| 20 | 2026-10-19 | 2C | With the backend stopped, the login button stayed on "Signing in…" for several seconds before the "Can't reach the server" message appeared. A hung server could keep it disabled forever. | Poor feedback on network problems. | Added a 15 second timeout to every API call (`AbortSignal.timeout`). | Resolved | Every network call needs a timeout. |
| 21 | 2026-10-19 | 2C | Vitest 5.x needs Node 22 or newer, but `frontend/package.json` says Node `>=20.9`. The newest Vitest (5.0.5) is only 4 days old. | Dev-only tool is stricter than the app. | Pinned the older `vitest@5.0.3` (19 days old, versions policy). The app itself still runs on Node 20.9+; only running tests needs Node 22+. | Workaround | Check the `engines` field of every new tool. |
| 22 | 2026-10-19 | 2C | The login page's "Forgot password?" link pointed to `/forgot-password`, which is built in layer 2C-2. | Link showed the 404 page until then. | Kept the link (spec requires it); built the page in 2C-2. | Resolved | Remove the gap by building 2C-2 next. |
| 23 | 2026-10-19 | 2C | Caps Lock hint and browser "Save password?" prompt cannot be triggered by browser automation. | Cannot verify two spec items myself. | Implemented per spec; marked as "owner to check" in the report. | Open | Say clearly which checks are manual. |
| 24 | 2026-10-19 | 2C-2 | In development React runs effects twice. The reset page removes the token from the address bar on the first run, so the second run saw no token and showed "Link not valid". | Reset link looked broken in dev. | Keep the first reading of the token in a ref. | Resolved | Anything that reads and then deletes data in an effect must survive a double run. |
| 25 | 2026-10-19 | 2C-2 | Pasting a reset link into a tab that was already on `/reset-password` only changes the part after `#`, so the page did not reload and kept showing the old state. | 29 | 2026-10-19 | 2C-2 | A shell command that wrote several documents failed to parse again (same as entry 12). | Lost a step. | Used the file-editing tools one file at a time. | Resolved | Never put long multi-file edits with quotes into one shell command. |
