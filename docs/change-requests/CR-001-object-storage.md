# CR-001: Replace MinIO with SeaweedFS as the object storage service

Follows the blueprint Change Request process (section 2). Status: **Approved by the owner in chat on 2026-10-20** (owner said "Start next phase" after the Phase 3 plan, which proposed this change). The owner can reverse it.

## 1. What must change and why
The blueprint names **MinIO** as the S3-compatible object storage (sections 8.6, 12.1, 21.2). On 2026-10-19 I checked the sources:
- The `minio/minio` GitHub repository is **archived** and its README says "THIS REPOSITORY IS NO LONGER MAINTAINED".
- There is **no `minio/minio` image on Docker Hub** (the API returns "object not found").
- Running unmaintained storage that holds every uploaded company document is a security risk.

## 2. What it touches
- Blueprint text only (service name). The **reason for the choice stays**: a local service with the same S3 API as cloud S3, so we can move to cloud storage later.
- Phase 3 compose service name is `storage` (generic) instead of `minio`.
- Credentials: `S3_ACCESS_KEY` and `S3_SECRET_KEY` instead of MinIO user/password (generated by `scripts/setup_env.ps1`).
- No database, API or security-rule change. No frozen item changes.

## 3. Additive solution
Application code uses our own `ObjectStorage` interface (`app/storage`) with one `boto3` (S3 API) implementation. SeaweedFS is only the service behind it. Switching to Garage, AIStor or real S3 later means changing settings, not code.

## 4. Options considered
| Option | Licence | Status (checked 2026-10-19) | Verdict |
|---|---|---|---|
| **SeaweedFS** | Apache-2.0 | Active, release 4.48 (28 Sep 2026), image `chrislusf/seaweedfs:4.48` (92 MB download) | **Chosen**: one container, simple S3 login file |
| Garage | AGPL-3.0 | Active, v2.4.1, 26 MB image | Good, but needs a cluster layout step even for one node |
| AIStor Free (MinIO company) | Free licence, not open source | Image location and terms not verified | Not chosen: unverified terms |
| Keep archived MinIO from an old image | AGPL-3.0 | Unmaintained | Rejected: security risk |
| Local disk | n/a | n/a | Rejected by the blueprint (cannot move to cloud cleanly) |

## 5. Decision
Use **SeaweedFS 4.48** behind the S3 storage adapter. Recorded as ADR 025 (supersedes the MinIO choice in blueprint section 12.1).

## 6. Consequences
- Blueprint says "see it in the MinIO console". SeaweedFS has no S3 console in our setup, so the check is `python -m app.scripts.storage_check` (lists keys and sizes, never content). An optional dev-only web UI is in `docs/BACKLOG.md`.
- The container runs as root inside the private network (needed for the generated login file); moving to non-root is in the backlog for Phase 9.
