# ADR 036: Continuous integration and quality gates (Phase 9A)

## Status
Accepted (2026-10-23). Part of the Phase 9 plan the owner approved ("plan ok"). The owner can reverse any item.

## Context
Blueprint section 14.3 lists eight CI gates (lint and format, types, unit tests with coverage on security modules, integration tests with PostgreSQL and pgvector, the leak suite, dependency and secret scans, frontend build with accessibility checks, image build). Until now the checks ran only on the developer's machine.

## Decision
- **One workflow** (`.github/workflows/ci.yml`) with five jobs: backend lint, frontend, secret scan, dependency scan, backend tests (types, leak gate, all tests, coverage gate, image build). Jobs run in parallel.
- **The backend tests run in Docker Compose**, the same way as locally, so CI and a developer machine behave alike. The two models are baked into the image and cached between runs with the GitHub Actions cache. A throw-away `.env` with random secrets is generated by `scripts/setup_env.sh` (a Linux and macOS twin of the Windows script); nothing is stored.
- **Types:** mypy runs inside the backend container (it needs the installed packages). The 36 existing type errors were fixed (names, optional values, annotations); no behaviour changed. Third-party packages without type information are ignored.
- **Lint:** ruff with the rule sets E, F, W, I, B and UP, line length 200; three rules are switched off on purpose (FastAPI's `Depends` in defaults, `zip(strict=)`, `timezone.utc`). Tests may use long dense tables.
- **Frontend lint:** ESLint 9 with the Next.js and TypeScript presets. Next.js 16's React Compiler advisory rules flag 21 places that use two long-standing patterns (loading data in an effect, an animated wrapper created inside a component). They are warnings with a ceiling of 21, so they can only shrink (backlog 44). **Prettier is not adopted:** reformatting the whole code base would hide real changes in the history.
- **Coverage gate:** at least 80 % over the security-critical modules (blueprint NFR-08). Measured today: 83 % over the whole backend.
- **Leak gate:** a separate, named step runs the canary scan, the access oracle and the evaluation first, so a leak is the first failure anyone sees.
- **Scans:** gitleaks over the whole history (a secret removed later is still leaked), pip-audit for Python and `npm audit` for the packages that ship to users (high and critical).
- **Dependabot** opens weekly update pull requests for pip, npm, Docker and Actions. A pull request template and `CONTRIBUTING.md` set the checklist; `.pre-commit-config.yaml` is optional.
- **Licence:** MIT.
- **Dockerfile order:** the models are downloaded before the other packages (backlog 31): a package change no longer downloads about 1 GB again.

## What the first scans found
- `pypdf` 6.19.0 had 8 known vulnerabilities (it parses uploaded PDFs). Upgraded to 6.21.1, which fixes all of them. The tests for parsing and ingestion pass.
- No secret in the whole git history (43 commits scanned).
- No vulnerable frontend package.

## How it is proven
Every step was run locally exactly as the workflow runs it (lint, types, frontend checks, scans, the leak gate, all 697 tests with coverage, the image build). The workflow file itself can only be proven by GitHub: the first run happens on the pull request.

## Consequences
- A first CI run builds the image without a cache (about 20 minutes); later runs are much faster.
- Lighthouse and axe checks come in 9C.
